# M17e 扩行填满（grow fill）：既成空洞回填设计

- 日期：2026-10-10
- 前置：M17d 扩行回填 + ED3 清历史（2026-10-09-m17d-grow-refill-design.md，tag m17d @ 527950d + bdec66c）
- 分支：contour

## 1. 目的与范围

消除 M17d 复验遗留的「不满屏」缺口：窗口缩拉后重新拉大，内容完整、
提示符光标位置正确，但屏幕底部残留既成空洞，提示符悬在半空。

**留痕证据**（spike 留痕 trace4，2026-10-09 17:48 用户真实慢拖，
114 事件约 40 个中间尺寸，已持久化 `~/.cache/zz-traces/spike-trace4.bin`
——/tmp 会被清理，trace3 丢失的教训）：

重放终态：native 非空=66/75 history=37 cursor=(48,65)；底部 r66-74
共 9 行空白。逐事件推演确认：

1. **内容零丢失**——终态三次 `ll` 完整（`scripts/` 在 r58）；
2. **底部 9 行空洞是 bash 在 75x32 窄窗时代擦出的既成空行**（当时
   r23-31），拉大时 M17d 按规格 §3.2 只回抽扩行增量 k=43 条历史，
   既成空行原样保留并随内容沉底；
3. contour 参照后端跑同一留痕：非空=25/75 history=71，残局更丑
   （r22/r23 重复完整提示符 + r25 乱码拼接行）——缺口为既存语义
   差异，非回归。

**根因**（代码实证 `src/screen/Screen.cpp` resizeBuffer 扩行分支）：
回抽请求量恒等于扩行增量 k，光标下方既成空行（b 行）被视为屏幕内容
保留，回填后仍占底部 b + (k - p) 行。用户核心诉求「无论怎么缩拉
最后内容完整且满屏」要求把既成空洞也纳入回填预算。

范围内：

- native 后端扩行分支的既成空洞回填语义（Screen 一处）
- Core 单元测试（空洞回填账 + 边界保护）
- 文档同步（Screen.cpp 注释、Architecture-v2 parity 登记、
  Scrollback-and-Reflow.md）
- compat 用例 26 偏离描述更新（偏离加深，登记同一条目）

范围外：

- contour 后端行为变更（第三方冻结）
- 缩行语义（M15 不变）
- readline 残行（trace4 r63/r64 半截提示符）：窄窗重绘死代尸体，
  在最终拉大前的 75x32 状态即已存在于屏幕上，非回填产物；终端侧无
  忠实修法（contour 同留痕更丑），本里程碑不处理

- spike 演示层改动

## 3. 核心机制：既成空洞回填

### 3.1 触发条件

沿用 M17d liveAtBottom 判定不变：Primary buffer 且光标下方所有行
均为空行（zzRowIsBlank：整行 cell 均 isEmpty；显式写入的空格非
isEmpty，视为内容）。光标下方有非空行（布局保护）、Alternate
buffer 的情形维持 M17d/M15 现状，本机制不触碰。

### 3.2 回填量与丢弃

触发时（扩 k 行，光标下方 b = oldRows - 1 - cursor.row 行全空）：

1. 丢弃光标下方全部 b 行既成空行（isEmpty 行，无内容可丢）；
2. 历史回抽请求量从 k 改为 **k + b**，经既有 HistoryPullCallback
   （M17d 折链对齐向下取整语义沿用，仅 n 初值从 min(k, H) 变为
   min(k + b, H)）；
3. 光标行号平移 = 实际拉入数 p（丢弃发生在光标下方，不影响光标行）；
4. resize 出口补空：底部空行数 = k + b - p。

历史充足（p = k + b）：底部零空行，屏幕填满，提示符沉底。

### 3.3 历史不足等价性证明

设历史可用 H，M17d 底部空行 = b + (k - min(k, H))；
方案 A 底部空行 = k + b - min(k + b, H)。

- H ≤ k：两者同为 b + k - H（方案 A 丢弃空行后以新空行补齐，净
  效果相同）；
- k < H < k + b：M17d 空 b 行，方案 A 空 k + b - H < b 行；
- H ≥ k + b：M17d 空 b 行，方案 A 空 0 行。

方案 A 在所有分支不劣于 M17d，历史充足时严格填满。

注：以上账以「实际拉入 p = min(请求量, H)」计。M17d 折链对齐向下
取整可能使 p 再少至多（链长 - 1）行，该差额两方案同样存在、底部
补空吸收，不改变比较结论（M17d 规格 §3.3 同口径）。

### 3.4 空行丢弃的链安全

被丢弃行整行 isEmpty。若某丢弃行 wrapped = true（属上方折链的空
续行）：删除等于截短链尾，链头及以上行内容完整，渲染无损失——
该续行本就无可见内容。若 wrapped = false：独立空行，直接删除无
影响。删除后不需要修补任何行的旗标（wrapped 语义为「本行与上一
行同链」，存续行与其上一行的关系未变）。

### 3.5 ED3/clear 交互

`clear`（含 ED3）后历史为空：p = 0，丢弃的 b 行空行由新空行补回，
净效果与 M17d 完全相同（§3.3 的 H = 0 分支），clear 意图不受
影响——拉大不会复活任何内容。

## 4. 与既有机制的交互

- resize 顺序不变：先列变 reflow（M16b/M17a/M17c 所在阶段），后
  行变 resize（本机制在行变阶段扩行分支），与 M17a Preserve
  （reflow 阶段豁免）正交；
- M15 缩行：裁光标下方行在前、压历史在后，语义不变；本机制是
  扩行侧的对称补全（缩行裁下方行，扩行丢下方空行）；
- M17d 折链对齐：实现位置在 native 后端 HistoryPullCallback 接线
  层，本机制只改 Screen 侧请求量（k → k + b），对齐逻辑零改动；
- 选区钉住：扩行顶插的坐标平移沿用 M17d 已核查路径；丢弃行在
  光标下方且为空，不承载选区内容；
- 代计数：回抽走 takeNewest，代计数递增已有，HistoryView/搜索
  自洽。

## 5. parity 与偏离登记

本机制属 M17d 已登记偏离（contour growLines 仅光标贴末行回抽）
的加深：回填预算从扩行增量扩到「增量 + 既成空洞」。compat 用例
26 条目更新描述，不新增登记类别。kitty/Windows Terminal 拉大即
填满，本机制向主流手感收敛。

## 6. 测试

Core 单测（Screen 装回调层级或 native 后端）：

1. 历史充足 + 光标下方空洞 → 扩行填满，底部零空行，光标沉底
   （新语义核心，行数账手工推演）；
2. 历史部分充足（k < H < k + b）→ 严格改进账：底部空行 =
   k + b - H，少于 M17d 的 b；
3. 历史为空 → 与 M17d 净效果等价（退化保护）；
4. 光标下方有非空行 → 不触发（M17d 用例回归保护）；
5. 折链对齐：请求量 k + b 参与向下取整，被取块首行为链头；
6. 空续行（wrapped=1 且 isEmpty）丢弃后上方链完整可渲染；
7. Alternate 扩行不动历史（M17d 用例回归保护）。

compat：用例 26 偏离描述更新。

**重放金标准**：`~/.cache/zz-traces/spike-trace4.bin` 终态期望
从「非空 66/75 + 底部 9 行空洞」变为「非空 = 75/75（history=37
足以覆盖 9 行缺口）、欠填报告 0、提示符沉底 r74」。欠填不变量
（resize 后屏幕非空行 < 行数 且 history > 0）常驻重放器检查。
重放器属诊断工具不入库，重建命令见 M17d 计划任务 4。

spike 复验手势：长路径目录 `ll` → 慢拖若干中间尺寸 → 拉回最大化，
预期屏幕填满、提示符沉底。

fuzz 路径不受影响。
