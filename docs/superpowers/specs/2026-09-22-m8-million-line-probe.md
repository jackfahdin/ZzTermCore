## 4. 归因初判与结论

两项不达标：RSS 峰值（6712.4MB 对 512MB）与全量 search（9880.34ms 对 5000ms）。逐项归因：

- **RSS 峰值——瓶颈在历史存储层（Cell 明文驻留）**。单元轨 1M 档 RSS 1294.3MB 与 ZzScrollback 自报 approxBytes 1274.0MB 几乎重合（1M 行 x 80 列 x sizeof(Cell)约 16B 的明文体量），即历史区 Cell 明文即是内存主体的全部，无其他隐性大户。facade 轨峰值显著高于稳态（mixed 1m 峰值 6712.4MB 对稳态 2776.7MB），差额来自 reflow 期间新旧两套历史结构短暂并存（mixed 经 soft wrap 约 2M 物理行，翻倍即约 2.6GB 增量）叠加 VT 流缓冲。候选优化方向：Cell 内存瘦身（直接降稳态与峰值基数）、warm LZ4 压缩层（冷历史压缩，命中峰值与稳态两项）。
- **全量 search——瓶颈在搜索扫描路径，不在访问路径**。单元轨 1M 档 lineAt 顺序全扫仅 31.67ms、随机 10 万次仅 11.30ms，证明 chunked 存储的行定位廉价；而 facade 全量 search 随档位严格 10 倍线性放大（ascii 572.88 -> 5697.09ms，mixed 991.46 -> 9880.34ms），耗时在逐 cell 文本提取与比对本身。候选优化方向：搜索增量索引（规格 §1 清单）；若先做 Cell 瘦身，扫描的缓存友好性也会顺带改善，可复测后再裁定是否仍需索引。
- **reflow 达标但余量不厚**：mixed 1m widen 4597.05ms 对 10s 阈值。reflow 本身是峰值 RSS 的放大器（见上），若后续做 RSS 优化需回归复测本项。lazy reflow 作为候选方向保留。
- **append 吞吐达标且近平直线性**（1M 档为 10k 档的 84.9%-102.0%），历史写入路径当前无瓶颈。

实验中规避的既有缺陷：src/history/ChunkedScrollback.cpp 的 trimToCapacity/lineAt 在裁剪后存在越界风险（已立项待报用户）。facade 轨 historyCap 按画像预留余量（Ascii lines+24、Mixed lines*2+24）使长跑全程不触发裁剪，故本矩阵数据不受该缺陷影响；此规避属实验设计，非 harness 问题，缺陷本体留待用户决策后另行处理。

结论：M8 测量波完成，矩阵数据全量入库。1M 档 5 项门控中 2 项不达标（RSS 峰值、全量 search），按规格 §5 流程进入决策点——是否启动优化波及方向选择（建议优先级：Cell 瘦身 / warm LZ4 先行，搜索增量索引视复测结果裁定）由用户决策，本里程碑测量部分到此收尾。

## 5. 门控修正记录

无。规格 §4 预设阈值量级合理（RSS 512MB 对应每行约 6.4B 的 Cell 目标体量，恰为优化波的目标锚点；search 5s 与 reflow 10s 均为交互可容忍量级），实测不达标项属实现现状而非阈值错误，按门控修正规则不作修正。

### 6.3 门控修正（已确认落账，2026-09-28 用户批准）

以下修正已按本节数值落定到 m8-million-line-design.md §4（RSS 拆两口径一行）；search 维持 5s 不动，不达标项移交搜索增量索引里程碑；其余项不修正。原值/新值/理由留痕如下：

| 门控项 | 原值 | 新值（建议） | 理由 |
|---|---|---|---|
| RSS 峰值 | 不超过 512MB（facade 轨 1m peak 较大者口径） | 拆两口径：单元轨 1m RSS 不超过 1100MB；facade 轨 1m peak 不超过 3500MB | 12B 瘦身使单元轨 1m RSS 实测 989.0/990.2MB（6.1），1100MB 为实测加约 11% 余量，与 M8b 规格 §5 预设候选一致；streaming reflow 消除峰值翻倍，facade 1m peak 实测 ascii 1515.8MB / mixed 3105.5MB（6.2），3500MB 为 mixed 实测加约 13% 余量。原 512MB 锚定每行约 6.4B 的 Cell 目标体量，超出本波 12B 方案可达范围（每行 12B 恰使 approxBytes 降至基线 76%），属阈值口径随实现路线修正而非放宽现状 |
| append 吞吐 | 不低于 10k 档的 50% | 不修正 | 复测 1m 对 10k lines/s 比值 ascii 8,607,993 / 8,658,946 = 99.4%、mixed 10,427,831 / 10,473,650 = 99.6%，继续达标且余量充足 |
| 全量 search | 不超过 5s | 不修正（维持 5s，本波复测判定仍不达标） | 复测 facade 1m ascii 5550.92ms / mixed 9691.16ms（6.2），较基线仅降 2.6% / 1.9%——12B 降内存流量对扫描耗时改善有限，瓶颈仍在逐 cell 文本提取与比对（§4 归因成立）。search 专项优化属 M8b 规格 §6 明确排除项，建议阈值不动，不达标项移交搜索增量索引里程碑裁定 |
| reflow 80->120 | 不超过 10s | 不修正 | 复测 facade 1m mixed widen 3880.51ms（6.2），较基线 4597.05ms 余量增厚，继续达标 |
| feed 吞吐 | 只记录不设门 | 不修正 | 复测 1m ascii 4.8 MB/s、mixed 8.0 MB/s（基线 4.5 / 7.6），记录 |

### 6.4 结论

- **内存目标达成**：单元轨 1m approxBytes 1274.0 -> 968.9MB（基线的 76.1%，契合 12B/16B 理论值）；RSS 1294.3/1294.4 -> 989.0/990.2MB（降 23.6% / 23.5%）。facade 轨稳态同步下降：ascii 1340.8 -> 1034.4MB、mixed 2776.7 -> 2163.7MB。
- **峰值翻倍消除（streaming reflow 生效）**：facade 1m peak ascii 3323.8 -> 1515.8MB（-54.4%）、mixed 6712.4 -> 3105.5MB（-53.7%）；单元轨进程峰值 3673.5 -> 1447.2MB（-60.6%）。peak 对稳态的倍率由基线 2.4-2.5 倍回落至 1.44-1.47 倍，reflow 期间新旧两套历史并存确已消除。
- **reflow 顺带提速**：facade mixed 1m widen 4597.05 -> 3880.51ms（-15.6%）、ascii 2675.37 -> 2344.12ms（-12.4%）；单元轨 mixed 1m widen 2126.26 -> 1714.26ms（-19.4%）。
- **search 复测结论：仍不达标**。facade 1m ascii 5550.92ms / mixed 9691.16ms 对 5s 阈值，较基线仅改善 2.6% / 1.9%，Cell 瘦身不解决扫描比对瓶颈，§4 归因维持成立；建议维持阈值并将不达标项移交搜索增量索引里程碑（见 6.3，已确认）。
- **回归证据**：linux-gcc-debug 50/50、m2-off-check 40/40、m2-shared-check 50/50、linux-clang-fuzz 2/2、doxygen 零警告；复测矩阵九条 bench 全部 exit 0，九份 JSON 入库 tests/perf/records/2026-09-28-m8b-*.json。
- **遗留项**：search 不达标项（待搜索增量索引里程碑）；ascii append 小幅回退 108.63 -> 116.17ms（+6.9%，-O0 噪声范围，append 吞吐门控 99.4% 达标不受影响）；mixed 画像 1m feed 21.7s 仍为重头（只记录项）。
