# M17c 整行擦除斩链（erase severs wrap chain）设计

- 日期：2026-10-08
- 前置：M17a 光标活动链 reflow 收链保护（2026-10-08-m17a-active-chain-guard-design.md，tag m17a）
- 分支：contour

## 1. 目的与范围

消除 M17a 复验发现的提示符残片事故：erase 操作不斩链导致 Preserve
保护了「僵尸折链」。

**事故链**（spike 留痕 `/tmp/spike-trace.bin`（19:25，25 事件）离线重放
+ 链标探针实证）：

1. 用户在长路径目录（62 字符提示符）下两次 `ll`，窗口从 271x75 拖到
   79x24 → 14x16 → 14x3，再拉回 271x75；
2. 窄窗期间 bash 每次 WINCH 重绘都**擦除并重写**提示符行，产生三代
   提示符尸体：第一代残 4 行（末行被 `\e[K` 擦除改写）、第二代残 2 行
   （其余被 `\e[2J` 清屏干掉）、第三代活 5 行；
3. 擦除没有斩断 wrapped 链标，三代尸体在缓冲区里粘成**一条 11 行连续
   折链**（探针实测 rows 64-73 wrapped=1、row 74 wrapped=0）；
4. M17a 的 Preserve 看到光标在链上，把整条僵尸链全部豁免收链。拉回后
   bash 只擦它认识的 5 行（第三代帧），前两代 6 行残尸永久留在屏幕上
   ——用户看到「路径碎成好几行」。

**根因**：EL/ED 擦除只清单元格，不动 wrapped 旗标。擦除的语义是「内容
死亡」，但折链还当它活着，收链保护与拼链提取都被死内容污染。

范围内：

- native 后端 erase 路径（EL/ED 系列）的斩链语义
- 历史/屏幕跨界斩链（被擦行的前驱可能已滚入历史）
- Core 单元测试（事故复刻 + 斩链规则单测）与 compat 偏离登记
- 文档同步（Scrollback-and-Reflow.md、API.md、已知外部问题章节）

范围外：

- contour 后端行为变更（第三方冻结；parity 偏离见 §4）
- ECH（`\e[X`）、DL/IL（`\e[M`/`\e[L`）的斩链（首版不含，§3.4 记录）
- spike 演示层改动
- 光标错位问题：上游 readline bug，终端侧不动（§5）
- M17b 不换行显示模式与横向滚动条（后续里程碑，正交）

## 3. 核心机制：整行擦除斩链

### 3.1 语义规则

*整行擦除 = 该行内容死亡 = 从折链上摘除。*

行 R 被整行擦除时：

- `R.wrapped = false`（斩断出链：R 不再续接到下一行）；
- 前驱行 P（R 的上一行，**可能已在历史区**）`.wrapped = false`（斩断
  入链：P 不再续接到 R）。

### 3.2 触发集合（首版）

- **EL 覆盖整行**：`\e[0K`（默认 `\e[K`）且擦除起点为列 0（典型形态
  `\r\e[K`）、`\e[2K`（整行擦除，任意光标列）；
- **ED 系列**覆盖到的所有屏幕行：`\e[0J`（下方全部整行 + 光标行剩余；
  光标行仅当光标在列 0 时才算整行覆盖）、`\e[1J`（上方全部整行 + 光标
  行开头；光标行仅当光标在末列时才算整行覆盖）、`\e[2J`（全屏整行）。
  `\e[3J` 当前被分发层忽略（NativeCsiDispatch case 'J' 只受理 p<=2，
  ED 3 不达 Screen），不在触发集合；`\e[2J` 只清屏幕不清历史，历史区
  内容不受影响（接缝链标由跨界斩链处理，§3.1）。

### 3.3 不斩链的情形

- **行尾部分擦除**：`\e[K` 起点不在列 0（如提示符行内局部改写）——
  视为对活内容的编辑，链标不动；
- **覆盖写**（无擦除直接改写单元格）：首版不动链。readline 的重绘路径
  恒为先擦后写，本规则已覆盖事故场景；
- **ECH（`\e[X`）/ DL / IL**：首版不斩，记录在案。DL 物理移除行对象，
  其链标影响留待出现实际事故再定。

### 3.4 效果（对照事故链）

- 第三代重绘前的擦除（`\e[K`+`\e[2J`）把第二代残尸的入链斩断；第二代
  重绘时第一代的末行已被 `\e[K` 擦除、入链斩断——三代不再粘连；
- 扩列 reflow 时光标链 = 仅活代 5 行，Preserve 精确保护 5 行；
- bash 拉回后的帧擦除（`\e[K` + `\e[A\e[K`×4）精确命中 5 行 → 屏幕
  零残片、listing 内容零损失；
- 死代残骸按普通规则收链成 1-3 条短行，留在滚动区上方（方案 A 接受的
  形态）；选区拼链（ZzSelectionText）跨代自然断开，无需改动。

### 3.5 降级边界

斩链只影响 wrapped 旗标，不删行、不动内容；即使某条链被误斩（exotic
应用对活链做整行擦除再续写），后果仅为该逻辑行在 reflow/选区中按硬行
处理，不产生内容破坏。

## 4. contour parity 偏离声明

本语义起，native 与 contour 后端在「erase 触及 wrapped 行」场景**有意
偏离**：native 斩链，contour 保持链标（contour 源码冻结，且该偏离与
M17a 的 Preserve 偏离同属差异化语义族）。相关 compat 用例改写为偏离
登记断言，docs/Architecture.md 与 API.md 的 parity 章节同步登记。

## 5. 已知外部问题登记：readline 8.3 光标错位（终端侧不处理）

M17a 复验中用户同时报告「光标停在提示符中间」。本次诊断完整闭环：

- **无终端 PTY 实验**（`/tmp/zz-resize-repro/bash_backspace_probe.py`，
  真 bash 5.3.9 + TERM=xterm-256color）：271→14→271 单序列即逐字节复刻
  现场（双写提示符 + 尾随 13 个 `\x08`）；无终端渲染器参与，证明字节流
  纯由 bash 算出；
- **上游确认**：readline 8.3 已知 bug——终端变宽时提示符从折行变为
  单行且含 2 段以上隐形字符（颜色码），readline 把光标放偏左，错位量
  = 隐形段字节长度（bug-readline 2026-08-10 Lucas Grigolon Varela 报
  告，实测 bash 5.3.9 复现）；维护者 Chet Ramey 确认 devel 已于
  2026-05 修复（commit 1e9f5e10b2），已发布补丁（≤8.3-p003）未带；
- **用户侧自愈**：该 bug 下 C-l 无效，打字会视觉覆盖提示符尾（逻辑无
  损），按回车换新提示符即恢复；根治等发行版更新 bash/readline；
- **终端侧结论**：xterm/konsole/contour 对同字节流渲染结果一致，无忠
  实修复手段，Core 与 spike 均不动。

本节内容同步写入 docs/Scrollback-and-Reflow.md「已知外部问题」小节。

## 6. 测试策略

1. **事故复刻**（native，Core 级）：合成三代重绘事件流（照留痕语
   义）——内容行 + 窄屏三代提示符重绘（含 `\e[K`、`\e[2J`、滚动）→
   拉回宽屏 → 模拟 bash 帧擦除+重印 → 断言：无残片行、内容零损失、
   光标位置与字节流一致；
2. **斩链规则单测**：`\r\e[K` / `\e[2K` / `\e[2J` 各斩链；`\e[K` 非
   列 0 起点不斩链；覆盖写不斩链；前驱在历史区的跨界斩链（擦屏幕 row
   0 时斩断历史末行 wrapped）；
3. **回归**：M17a 全部测试 + 基线 57 例 + contour 对照重放（native 断
   言斩链后形态，contour 登记偏离）；
4. **留痕重放验证**：`/tmp/zz-resize-repro/replay` 对同一份
   spike-trace.bin 重放，native 终态应由「6 行残片」变为「残片消失、
   内容完整」（人工验证步骤，不入库）。
